ORBMEKA — ORGANISATION DU PROJET

Ouvrez project.godot dans Godot, puis utilisez F5. Il n'est pas nécessaire
d'ouvrir chaque fichier. La version 0.0.2.7 range les fichiers sans modifier
le fonctionnement du jeu.

LES DOSSIERS
scenes/ contient main.tscn (accueil et menus) et world.tscn (partie).
scripts/ contient le code GDScript : app pour les menus, world pour les blocs
et le monde, player pour le joueur, terrain_generator pour les collines,
world_catalog pour les noms/graines, action_timing pour les délais,
controls et key_combos pour les touches (deux touches par action depuis 0.0.3.27),
launcher pour télécharger et lancer les versions (0.0.3.28, user://launcher/),
ui_theme pour le thème des menus et menu_showcase pour le fond 3D de l'accueil
(vitrine de la nouveauté, à mettre à jour à chaque version).
tests/ contient les vérifications automatiques, lancées sans fenêtre.
docs/ contient le guide détaillé README.md et cette note.
docs/idees/ garde des images d'idées pas encore dans le jeu (pour plus tard).
idee/ garde les prototypes de chaque nouveau personnage (nom-1.png à nom-3.png,
rendus dans Blender), pour comparer ; Godot l'ignore (fichier .gdignore).
sources_blender/personnages.blend contient les modèles des personnages et les
scripts qui les construisent (textes orbmeka_*.py dans Blender) ; ils sont
exportés en .glb dans assets/characters/, lus par le jeu.
L'icône icon.svg reste à la racine avec son fichier icon.svg.import :
inutile de créer un dossier de ressources pour cette seule image.

LES FICHIERS À CONSERVER
project.godot décrit le projet, sa version, sa scène de départ et ses réglages.
Les fichiers .gd sont les scripts ; les .tscn décrivent les scènes.
Les fichiers .gd.uid identifient les scripts de façon stable pour Godot.
Gardez-les avec les sources, notamment lors d'un déplacement.
icon.svg.import conserve les options d'importation de l'icône : ce n'est pas
l'image elle-même. Godot peut le régénérer, mais ses réglages sont à préserver.
README.md, à la racine, renvoie vers docs/README.md et les explications.
docs/HISTORIQUE.txt liste les versions (lu par l'écran Historique du jeu, depuis 0.0.2.14).
project.godot.before-prototype est une copie de la toute première configuration,
pas la configuration active : conservée comme référence, elle ne lance pas le jeu.

LES FICHIERS TECHNIQUES
.godot/ est le cache local de Godot : imports calculés, index, données d'éditeur
et journaux/tests temporaires. Godot peut le recréer depuis les sources.
Ce n'est ni votre code ni l'archive du projet ; laissez l'éditeur le gérer.
.editorconfig indique l'encodage ; .gitattributes les conventions de texte ;
.gitignore les fichiers à ignorer si Git est utilisé. Aucun dépôt Git n'est créé.
Les dossiers existants export_templates/, feature_profiles/, script_templates/
et text_editor_themes/ sont actuellement vides et restent en place.

DONNÉES ET ARCHIVE
Les noms, graines et modes personnels sont dans user://worlds.json, hors des sources.
Les constructions ne sont pas sauvegardées. La copie vérifiée 0.0.2.6 reste
hors du projet, dans le dossier voisin Archives/OrbMeka/orb-meka 0.0.2.6.
Depuis 0.0.2.8, addons/history_export/ contient un petit plugin d'éditeur
qui inclut docs/HISTORIQUE.txt lors des exports. Gardez ses fichiers sources.
Le README à la racine et docs/README.md restent les points d'entrée du guide.

Depuis 0.0.2.10, scripts/user_settings.gd valide et conserve les attributs
globaux, séparément des noms/graines des mondes. Depuis 0.0.3.6, un fichier par
menu de Paramètres, nommé d'après lui : user://parametres-generaux.json,
user://video.json et user://attributs.json (l'ancien settings.json n'est plus que lu) ;
depuis 0.0.3.12, user://controles.json (touches, scripts/controls.gd) ;
depuis 0.0.3.16, user://personnage.json (personnage, scripts/character_preview.gd).
Sous Windows, user:// est %APPDATA%\Godot\app_userdata\OrbMeka\.
