ORBMEKA — ORGANISATION DU PROJET

Ouvrez project.godot dans Godot, puis utilisez F5. Il n'est pas nécessaire
d'ouvrir chaque fichier. La version 0.0.2.7 range les fichiers sans modifier
le fonctionnement du jeu.

LES DOSSIERS
scenes/ contient main.tscn (accueil et menus) et world.tscn (partie).
scripts/ contient le code GDScript : app pour les menus (0.0.4.21 : en cinq parties empilées,
app_base → app_controls → app_launcher → app_settings → app ; constantes et variables dans
app_base), world pour les blocs
et le monde, player pour le joueur, terrain_generator pour les collines,
world_catalog pour les noms/graines, action_timing pour les délais,
controls et key_combos pour les touches (options, en même temps, après depuis 0.0.4.20),
launcher pour télécharger et lancer les versions (0.0.4, user://launcher/,
versions jouées dans user://launcher/versions-jouees.json depuis 0.0.4.1),
ui_theme pour le thème des menus et menu_showcase pour le fond 3D de l'accueil
(vitrine de la nouveauté, à mettre à jour à chaque version).
tests/ contient les vérifications automatiques, lancées sans fenêtre.
docs/ contient le guide détaillé README.md et cette note.
docs/idees/ garde des images d'idées pas encore dans le jeu (pour plus tard).
docs/idees/personnages/ garde les prototypes de chaque nouveau personnage (nom-1.png à nom-3.png,
rendus dans Blender), pour comparer ; Godot l'ignore (fichier .gdignore).
Les fichiers Blender (.blend) sont rangés hors du dépôt, dans ../Archives OrbMeka/Blender :
personnages.blend contient les modèles des personnages et les
scripts qui les construisent (textes orbmeka_*.py dans Blender) ; ils sont
exportés en .glb dans assets/characters/, lus par le jeu.
sources_blender/arbres/ contient les scripts des arbres (pommier, noisetier) : generer_arbres.py (construit les
modèles détaillés et enregistre arbres_detail.blend dans les archives Blender), version_jeu.py (version légère exportée dans assets/trees/, lue par
scripts/trees.gd), presentation.py (rendu d'aperçu) ; voir son README.md.
L'icône icon.svg reste à la racine avec son fichier icon.svg.import :
inutile de créer un dossier de ressources pour cette seule image.

LES FICHIERS À CONSERVER
project.godot décrit le projet, sa version, sa scène de départ et ses réglages.
Les fichiers .gd sont les scripts ; les .tscn décrivent les scènes.
Les fichiers .gd.uid identifient les scripts de façon stable pour Godot.
Gardez-les avec les sources, notamment lors d'un déplacement.
icon.svg.import conserve les options d'importation de l'icône : ce n'est pas
l'image elle-même. Godot peut le régénérer, mais ses réglages sont à préserver.
README.md, à la racine, renvoie vers docs/README.md et les explications.
docs/HISTORIQUE.txt liste les versions (lu par l'écran Historique du jeu, depuis 0.0.2.14).
(0.0.4.21 : l'ancienne copie project.godot.before-prototype et un main.tscn inutilisé à la racine ont été
retirés ; ils restent dans l'historique Git.)

LES FICHIERS TECHNIQUES
.godot/ est le cache local de Godot : imports calculés, index, données d'éditeur
et journaux/tests temporaires. Godot peut le recréer depuis les sources.
Ce n'est ni votre code ni l'archive du projet ; laissez l'éditeur le gérer.
.editorconfig indique l'encodage ; .gitattributes les conventions de texte ;
.gitignore les fichiers à ignorer si Git est utilisé. Aucun dépôt Git n'est créé.
Les dossiers existants export_templates/, feature_profiles/, script_templates/
et text_editor_themes/ sont actuellement vides et restent en place.

DONNÉES ET ARCHIVE
user://worlds.json reste l'index des mondes, hors des sources.
Depuis 0.0.5, les blocs posés et cassés, la position et le regard sont sauvegardés.
Chaque monde a son dossier user://mondes/<identifiant>/ : monde.json (nom, graine,
mode), joueur.json (position et regard) et, depuis 0.0.5.1, zones/zone_X_Y_Z.bin
(changements compressés par zone : blocs et, depuis 0.0.5.8, points du terrain lisse).
L'ancien zones/modifications.json est converti,
puis conservé sous zones/modifications-etape1.json.
Les archives restent hors du dépôt dans ..\Archives OrbMeka\ : une copie seulement au début de chaque
nouvelle série (0.0.6, 0.0.7…). Toutes les versions sont de toute façon sur GitHub (tags et Releases).
Ne jamais écraser une archive existante.
Depuis 0.0.2.8, addons/history_export/ contient un petit plugin d'éditeur
qui inclut docs/HISTORIQUE.txt lors des exports. Gardez ses fichiers sources.
Le README à la racine et docs/README.md restent les points d'entrée du guide.

scripts/user_settings.gd conserve les réglages globaux séparément des mondes.
Chemins actuels : user://parametres/parametres-generaux.json, video.json,
attributs.json, controles.json, personnage.json et menus.json dans le même dossier.
Les anciens fichiers à la racine de user:// servent à la migration et à la
compatibilité avec les anciennes versions du launcher.
Sous Windows, user:// est %APPDATA%\Godot\app_userdata\OrbMeka\.

TERRAIN LISSE — PREMIÈRE VERSION LIVRÉE EN 0.0.5.8
Zones de 8 × 8 × 8 mètres. Chaque bloc de 1 m de côté est partagé en 2 × 2 × 2 :
8 sous-cellules au total, de 50 cm de côté et de 1/8 du volume chacune.
Une zone contient donc 16 × 16 × 16 sous-cellules. Une grille de sommets
incluant les deux bords compte 17 sommets par axe, pas 16 points.
scripts/smooth_terrain.gd : densité par point (calculée depuis la graine, seuls les points
changés sont gardés), surface lisse par zone, gestes creuser / ajouter de 50 cm.
Les points changés sont enregistrés dans le champ « densite » des fichiers de zone
(format 3 ; le format 2, blocs seuls, reste lisible). Base indestructible à 4 m sous le sol.
scripts/surface_job.gd (0.0.7.20) : le même calcul de surface d'une zone, découpé en petites étapes
(3 ms au plus par image en jeu) ; smooth_terrain.prepare_step prépare de même la graine (montagnes,
lacs, rivières, crevasses, grottes) pour la vitrine de l'accueil. Résultats identiques (tests/surface_job_test.gd).
scripts/terrain_workers.gd (0.0.8.13) : fils de calcul du terrain (2 au plus), chacun avec sa copie du terrain (même graine) :
hauteurs et surfaces des colonnes sans changement du joueur autour, relevés du lointain ; le fil principal monte les morceaux.
Mêmes nombres que le fil principal (tests/workers_test.gd). MULTICOEUR=0 les coupe, COEURS=n en impose le nombre (mesures).
tools/mesure_perf.gd (0.0.7.20) : mesures sur PC (accueil, ouverture, marche en forêt), fenêtre hors écran.
tools/mesure_ouverture.gd (0.0.8.11) : ouverture d'un monde comme sur le Web (écran de chargement, rendu Compatibility), durées, images lentes, tâches.
Optimisation (0.0.8.14, rapport hors du dépôt : ..
apport-optimisation-0.0.8.14.md) :
tools/mesure_gpu.gd : temps de la carte graphique à 4 endroits (départ, forêt, lac, rivière), mesures par paires (avec, sans,
avec) ; QUALITE, ECHELLE, SORTES (cacher), EFFETS (couper), APPLIQUER (réglages à essayer). --gpu-index 1 : la Radeon 610M.
tools/mesure_memoire.gd : tours du monde en vol, mémoire, objets, orphelins et tailles des listes du monde.
scripts/diagnostic.gd : sortes de choses dessinées (terrain, herbe, lointain, eau, arbres…), effets (ciel, brume, ombres…) et
réglages à essayer, endroits de mesure ; scripts/web_diagnostic.gd : la même chose sur le Web (console de Chrome,
window.orbmeka). scripts/quality_hint.gd : propose une fois la qualité Performance sur un PC trop lent (menus.json).
tools/squelettes.gd (0.0.7.21) : calcule d'avance les branches de chaque modèle d'arbre (assets/trees/squelettes/,
à relancer si un modèle change). Paramètres → Vidéo → Qualité d'affichage : préréglages dans user_settings.gd (PRESETS).
tests/inventory_more_test.gd (0.0.7.29) : mode choisi à la création, Jeter (zone, hors de la fenêtre, J), bouton « + » (variantes, détails), D et Échap.

_floating_rock_cubes), cailloux posés sur le sol dessiné (_snap_pebbles), cailloux, rochers et objets qui suivent le sol creusé
(smooth_terrain.gd floor_at, world.gd _objects_follow, _rock_drop, ground_items.gd rest_again), génération 34 (aucun caillou

tools/mesure_physique.gd (sans fenêtre).
tests/perf_guard_test.gd (0.0.7.21) : garde-fou de vitesse (travail de fond dans son budget par image).

MONDES PERSONNALISÉS (0.0.5.16)
scripts/world_generation.gd définit les dix fréquences et l'algorithme personnalisé version 1.
Le champ generation de monde.json et de l'index est propre à chaque monde. Absent ou vide :
génération historique inchangée. Les réglages vidéo, dont la portée de l'herbe, restent globaux.
